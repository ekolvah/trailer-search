## Context

`HeuristicStrategy` (`src/trailer_search/strategy.py`) фильтрует кандидатов по названию и году и ранжирует по
`(is_ru, cast_hits, trailer_signal)`; `_queries` (`src/trailer_search/retrieval.py`) строит запросы из
названий и `year`. Воспроизведение и причина — в proposal.md, **Why**.

## Standard approach

- Разбор сезона из названия релиза — guessit (https://github.com/guessit-io/guessit, свойство `season`) и
  parse-torrent-title. Не подходят: новая зависимость ради одного номера (§VII), правила рассчитаны на имена
  файлов, а русских форм вроде `2-й сезон` в guessit нет. Берём одно регулярное выражение на формы, которые
  реально встретились в выдаче (решение 3).
- YouTube Data API `search.list` (https://developers.google.com/youtube/v3/docs/search/list) не фильтрует по
  сезону; сузить выдачу можно только текстом `q`. yt-dlp `ytsearchN:` — тоже только текстом.
- Наблюдение 2026-11-16, `YtDlpRetriever()._search_one(q)` на живом YouTube:
  - `Джентльмены 2 сезон trailer` → `3xow3-n2VQM` «Джентльмены (2 сезон) - …», `01IeKpHvgvM` «The Gentlemen:
    Season 2 | …», `jsU6-0uOIgE` «ДЖЕНТЛЬМЕНЫ 2 СЕЗОН (2026) | …», `q9tPf_FwQcg` «Джентльмены (2 сезон) — …»,
    `-j9LFgQqMAQ` «Джентльмены · 2-й сезон · …» — все 5 про 2-й сезон;
  - `The Gentlemen season 2 2026 trailer` → 5 роликов, у всех `Season 2`;
  - `The Gentlemen season 2 trailer` (запрос плана) → `01IeKpHvgvM`, `aOY7HTQlsSo`, `NGu-GD-Bk7g`, `Ks4qEmL_6sw`,
    `tridpi1XcaQ` — у всех `Season 2`, годы в названиях 2026 и 2025;
  - `Джентльмены 2 сезон 2026 trailer` — та же выборка, что и без года, т.е. год в запросе сезона ничего не
    добавляет.

## Decisions

1. **Только `season`, без `season_year`.** Год сезона нужен лишь затем, чтобы кандидат сезона прошёл проверку
   года. Решение 2 пропускает с сезоном любой год не раньше `year`, а запросы без года находят
   ролики нужного сезона (см. наблюдение выше). Владелец выбрал этот вариант 2026-11-16.
   Альтернатива — `season_year` в запросе и в списке допустимых лет: лишнее поле, а если у объявленного сезона
   нет даты, его не заполнить.
2. **С сезоном `year` — нижняя граница года.** Корень проблемы: `year` сериала — год 1-го сезона, поэтому
   точное совпадение года неверно для любого ролика сериала, а не только для помеченного сезоном.
   `title_year_matches(title, year, *, at_least=False)`: при `at_least=True` в названии нет года раньше `year`;
   `_relevant` передаёт `at_least=profile.season is not None`. Старый одноимённый тайтл (фильм «The Gentlemen»
   2019) по-прежнему отсекается. Альтернатива — снимать проверку года только у кандидата, который называет
   сезон: это особый случай, и он пропускает старый тайтл с тем же номером сезона.
3. **Один разбор сезона: `title_season(title) -> int | None` в `text.py`**, рядом с `title_year_matches`. Одно
   выражение, скомпилированное на уровне модуля, с группой номера, применяется к `normalize_title(title)` и
   распознаёт формы из спеки (Candidate ranking); ведущие нули снимает `int()`. Альтернатива — проверка
   «называет ли N» с номером, подставленным в шаблон: шаблон пересобирается на каждый вызов, а «без пометки»
   пришлось бы выяснять отдельно. Словесные формы («второй сезон») не поддерживаются: в выдаче их не было.
4. **Сезонный ключ стоит первым в `_rank`**: `(season_hit, is_ru, cast_hits, trailer_signal)`, где
   `season_hit = parsed == N or (parsed is None and N == 1)`; считается один раз на кандидата. Английский
   трейлер нужного сезона лучше русского трейлера старого сезона — потребитель просил именно этот сезон.
   Без `season` `season_hit` всегда 0, порядок прежний, и поэтому baseline на golden-наборе не меняется. Для
   N = 1 ролик без пометки сезона тоже считается попаданием: у односезонного сериала трейлеры обычно без
   пометки, и иначе каждый такой сериал получал бы ложную пометку о замене.
5. **Замена видна в `reason` и в логе.** Если `season` задан, а `season_hit` у лучшего ключа равен 0, к причине
   добавляется суффикс `; season N fallback` (суффикс, чтобы `ambiguous…` осталось в начале строки, как
   требует Candidate ranking), и пишется `logger.warning` с названием и сезоном (§IV). Confidence не меняем:
   уверенность в выборе среди оставшихся кандидатов прежняя, а сам факт замены несёт `reason`.
6. **Запросы с сезоном** — `<ru> N сезон trailer` / `<orig> season N trailer`, без года, ветвь в `_queries` над тем же списком `titles`: оригинальный запрос, как и раньше, только при непустом и
   отличном `original_title`.
   С годом 1-го сезона запрос тянет ролики 1-го сезона.
7. **Проверка входа.** `FilmProfile.__post_init__` бросает `ValueError` при `season is not None and season < 1`.
   Это новый класс ошибки входа, поэтому проверка добавляется в этом же PR (§VI).
8. **Выпуск.** `pyproject.toml` version → 0.2.0, в README тег установки `v0.2.0`. Тег `v0.2.0` ставится на
   merge-коммит после одобрения, с согласия владельца, как `v0.1.0` в прошлом изменении.

## Risks / Trade-offs

- [Более поздний одноимённый тайтл проходит нижнюю границу года] → принято: запрос `<название> N сезон` тянет
  нужный сериал; live-сценарий проверяет основной случай.
- [Поле `season` добавлено, но lampa-mediacenter его не передаёт] → тогда поведение прежнее; передачу сезона
  делает lampa-mediacenter#64.
- [Ролик со словесной пометкой сезона или с пометкой на другом языке не распознаётся] → он считается
  кандидатом без сезона, попадает в замену с видимой пометкой и не теряется.

## Migration / Rollback

Новое поле необязательное, у него есть значение по умолчанию: v0.1.0-вызовы работают без изменений. Откат —
вернуть пин на `v0.1.0` в потребителе.
